# ADR 0000: アーキテクチャ上の意思決定をADRとして記録する

## ステータス

採用

## コンテキスト

cjong4には、牌配置の表現、状態遷移の形式、プレイヤーへの情報公開範囲など、実装全体へ影響する設計判断があります。コードと概要文書だけでは、何を選んだかは分かっても、選んだ理由や受け入れた結果が失われやすくなります。

設計変更時に過去の前提を確認でき、同じ議論を繰り返さずに判断できる記録方法が必要です。一方で、記録自体が負担となって更新されなくなることは避ける必要があります。

## 決定

重要なアーキテクチャ上の意思決定をArchitecture Decision Record（ADR）として `doc/adr` に記録します。

各ADRはMichael Nygardのシンプルな形式を採用し、「ステータス」「コンテキスト」「決定」「結果」の4項目で構成します。タイトル、見出し、ステータス値、本文は日本語で記述します。

ファイル名は4桁の連番と、判断を表す英語のkebab-caseを組み合わせます。採用済みのADRは削除せず、判断を変更する場合は新しいADRを追加して以前のADRを「置換済み」とします。

## 結果

- 設計判断、その理由、受け入れた利点と制約をコードとともに追跡できます。
- 新しい参加者が現在の構成に至った背景を確認できます。
- 設計変更では、関連するADRの確認と新しいADRの作成が必要になります。
- ADRは決定時点の記録であり、現在の構成全体の説明は `doc/architecture.md` に維持します。
