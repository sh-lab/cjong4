# ADR 0003: プレイヤーごとにマスク済みビューを提供する

## ステータス

採用

## コンテキスト

`cj4_mahjong` は山の並びと全プレイヤーの手牌を含む完全状態です。これをプレイヤーの意思決定処理へ渡すと、本来見えない情報へアクセスでき、AI、ネットワーク対局、UIの境界で情報漏えいが起こります。

一方で、手牌、捨牌、面子、ドラ表示牌、立直状態、槍槓対象牌など、合法手の選択に必要な公開情報は一貫した形式で提供する必要があります。

## 決定

プレイヤーデリゲートには `cj4_mahjong` を渡さず、対象プレイヤーごとに生成した `cj4_player_view` を渡します。

`cj4_player_view.locations` は完全状態と同じ `cj4_location` 配列形式を使用し、自分の手牌と公開情報を保持します。山と他家の手牌などの非公開部分は `CJ4_LOCATION_NONE` でマスクします。

ツモ牌、最新捨牌、槍槓対象牌など、`locations` の公開範囲だけでは識別できない情報は、フェーズに応じて専用フィールドへ格納します。managerは合法アクションも同時に提供し、デリゲートはその中から1つを選択します。

## 結果

- プレイヤーの意思決定境界で、完全状態の非公開情報を隠せます。
- 完全状態とビューの双方で同じ `cj4_location_collect_*` APIを利用できます。
- UI、AI、リモートプレイヤーへ渡す情報の契約が明確になります。
- ビュー生成時に136要素のマスキング処理が必要ですが、固定された小さな上限として受け入れます。
- 新しい状態フィールドを追加する場合、各プレイヤーへの公開可否とビューへの反映方法を明示する必要があります。
