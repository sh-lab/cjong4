# ADR 0002: 値ベースの純粋な状態遷移を使用する

## ステータス

採用

## コンテキスト

麻雀の進行には、選択可能な行動の判定、行動後の状態、得点計算、局の終了判定など、多数の分岐があります。共有された可変状態や隠れたキャッシュに依存すると、呼び出し順による差異が生じ、再現、テスト、AI探索が難しくなります。

利用側がUI、AI、通信、ログなど異なる実行環境を選べるよう、ゲームロジックを外部の副作用から分離する必要があります。

## 決定

公開するcoreの状態遷移は、状態値と明示的な引数を入力として受け取り、遷移後の `cj4_mahjong` を値として返します。

グローバルまたはstaticな可変状態を使用せず、動作に必要な情報は状態または引数へ含めます。内部の更新関数は、公開状態遷移が作成した局所的な状態値を組み立てるためにだけ使用し、外部からの正規の状態変更には公開の `cj4_do_*` APIを使用します。

## 結果

- 同じ入力状態、ルール、アクションから同じ出力状態を再現できます。
- 各状態遷移を独立してテストでき、AIの分岐探索やログからの再実行に利用できます。
- UI、通信、永続化などの副作用を利用側へ分離できます。
- 状態値のコピーが発生しますが、状態サイズが固定され、挙動の単純さを優先するため受け入れます。
- 新しい処理では、隠れた状態を導入せず、必要な入力をAPIまたは状態へ明示する必要があります。
