# ADR 0001: locationsを牌配置の正規状態にする

## ステータス

採用

## コンテキスト

麻雀の局状態では、山、手牌、捨牌、面子、ドラ表示牌など、同じ物理牌に関する情報が複数の配列へ現れます。それぞれを独立した正規データとして保持すると、牌の移動ごとに複数箇所を更新する必要があり、不整合や重複が生じます。

cjong4は同じ牌種の4枚も区別し、物理牌の同一性と履歴を追跡する必要があります。また、完全状態からプレイヤー向けの部分情報を生成できる表現が必要です。

## 決定

136枚の物理牌IDを添字とする `cj4_location locations[CJ4_TILE_ID_COUNT]` を、牌配置の正規状態とします。

各 `cj4_location` は、元の山位置、捨牌情報、手牌または面子の配置情報、捨牌履歴情報を4バイトで保持します。山、手牌、捨牌、面子、ドラ表示牌は、必要なときに `locations` を走査して復元します。

ツモ牌、最新捨牌、山の進行位置など、頻繁に参照し、`locations` だけでは一意に特定できない小さな値は状態に直接保持します。

## 結果

- 物理牌ごとの現在位置と履歴を一箇所で管理できます。
- 山、手牌、捨牌、面子の重複した正規データと同期処理が不要になります。
- 状態の構造比較と、プレイヤー向け情報のマスキングを決定的に行えます。
- 逆引きには最大136要素の走査が必要ですが、固定された小さな上限として受け入れます。
- 新しい配置情報を追加する場合、4バイト表現、不明値、復元APIとの整合性を維持する必要があります。
