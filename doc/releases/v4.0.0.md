# v4.0.0 リリース準備

ステータス: 開発中・未リリース。公開APIの変更を含むため、利用側の再コンパイルと呼び出し箇所の移行が必要です。

## 修正内容

- チー／ポン後に合法な打牌が1枚も残らない場合、coreの鳴き判定がfalseを返します。managerもこの判定を使い、行き詰まる鳴きを提示しません。
- `cj4_do_chi()`／`cj4_do_pon()` も同じルールで検証します。不正な鳴きはDebug／Releaseとも入力状態を変更せず返します。
- `cj4_can_chi()` と `cj4_can_chi_with_tile()` の判定を統一します。色をまたぐ「9萬＋1筒・2筒」などを概略判定だけが許可する不一致を解消します。
- チー／ポンは4面子がある状態への追加、重複牌、無効牌、手牌外の牌を拒否します。喰い替え許可時も、鳴き後の手牌が空になる鳴きを拒否します。
- 打牌の `cj4_can_discard()`／`cj4_do_discard()` は、第2引数に `rules` を受け取ります。
- Releaseビルドでもテストのassertを有効にします。ライブラリ本体は通常のRelease設定でビルドし、その挙動をassertが有効なテストから検証します。

## API移行

チー／ポンの6関数は、第2引数に `const cj4_rules *rules` を追加します。旧シグネチャの互換ラッパーはありません。

```c
cj4_can_chi(state, rules);
cj4_can_chi_with_tile(state, rules, tile1, tile2);
cj4_do_chi(state_value, rules, tile1, tile2);

cj4_can_pon(state, rules, player);
cj4_can_pon_with_tile(state, rules, player, tile1, tile2);
cj4_do_pon(state_value, rules, player, tile1, tile2);
```

打牌APIのv3からv4への移行は以下のとおりです。第2引数に対局の `const cj4_rules *rules` を渡します。

| v3のAPI | v4のAPI |
| --- | --- |
| `cj4_can_discard(state, tile)` | `cj4_can_discard(state, rules, tile)` |
| `cj4_can_discard_with_rules(state, rules, tile)` | `cj4_can_discard(state, rules, tile)` |
| `cj4_do_discard(state, tile)` | `cj4_do_discard(state, rules, tile)` |
| `cj4_do_discard_with_rules(state, rules, tile)` | `cj4_do_discard(state, rules, tile)` |

鳴きの判定・実行、その後の打牌には同じルールを渡してください。`NULL` は既存のルール対応打牌APIと同様に、喰い替え禁止を適用しない明示的な指定です。`cj4_rules_default()` と同じ意味ではありません。通常の対局ではプリセットから生成した実際のルールを渡します。

使用牌を指定しない `cj4_can_chi()`／`cj4_can_pon()` は、合法な使用牌の組合せが少なくとも1つある場合にだけtrueを返します。実行前の最終判定には、実際に使用する物理牌IDを `_with_tile()` に渡します。

managerの公開APIと状態構造体のレイアウトは変更しません。ただし、coreの呼び出し規約が変わるため、v3のオブジェクト／静的ライブラリとの混在はできません。

CMakeの利用側は `find_package(cjong4 4 CONFIG REQUIRED)` に更新します。`SameMajorVersion` の設定により、v3を要求する利用側にv4は互換パッケージとして選択されません。

## 関連プロジェクトの移行箇所

以下は調査時点で確認した移行箇所です。関連リポジトリの変更・リリースは本ブランチに含みません。

- `cjong4-web/src/game_session.c`: `cj4_do_chi()`／`cj4_do_pon()` の直接呼び出しに対局の `rules` を渡し、`cj4_do_discard_with_rules()` を `cj4_do_discard()` に変更する。
- `cjong4-mjai/CMakeLists.txt`: `find_package(cjong4 3.3 ...)` をv4へ更新する。
- `cjong4-opponent/CMakeLists.txt`: `find_package(cjong4 3.3 ...)` をv4へ更新する。
- `cjong4-move-evaluator/CMakeLists.txt`: `find_package(cjong4 3.3.0 ...)` をv4へ更新する。
- ソースを直接組み込む構成も、v4のヘッダーとライブラリを揃えて再ビルドする。

## 検証範囲

coreの回帰テストでは3色・チーの3つの取得位置・席順・喰い替え有効／無効／NULL・打牌が1枚だけ残る場合・色の境界・ポン・空の残り手牌・不正な引数・4面子済みの状態を確認します。

managerの回帰テストでは、鳴けない場合に次のツモへ進むこと、鳴いた場合に打牌候補が残り、次のstepで実際に打牌できることを確認します。

リリース前には、関連プロジェクトの移行後の結合テストとCIのGCC／MSVC検証も必要です。
