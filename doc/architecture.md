# cjong4 アーキテクチャ概要

## 目的と対象範囲

cjong4 は、4人打ち日本式リーチ麻雀の局進行と得点処理を提供するISO C11ライブラリです。UI、通信、永続化、対局者AIは扱わず、それらから利用できる決定的なゲームロジックを提供します。

設計の中心は次の3点です。

- 136枚の物理牌を個別に識別し、`locations[136]` を牌配置の正規状態にする
- 状態を値として受け取り、新しい状態値を返す
- 対局者には、その対局者から見える情報だけを含むビューを渡す

これらの判断の背景は[ADR一覧](adr/README.md)に記録します。

## 構成要素と責務

### core

`include/cjong4/core` と `src/core` は、完全情報を使ったゲーム規則と状態遷移を担当します。

- `cj4_mahjong`: 対局の完全状態
- `cj4_rules`: ルール設定とプリセット
- `cj4_can_*`: アクションが可能かを判定する公開API
- `cj4_do_*`: 入力状態から遷移後の状態を返す公開API
- `cj4_location_collect_*`: 正規状態から手牌、捨牌、面子、ドラ表示牌を復元するAPI
- `cj4_*` 手牌解析API: 完全状態からシャンテン数、形テン、待ち牌種と見えていない枚数を計算
- 得点、役、流局、途中流局、連荘、終局の判定

公開APIからの正規の状態変更は `cj4_do_*` を通します。`src/core` 内の更新関数は、公開関数が作成した状態値の局所的な組み立てにだけ使います。

### manager

`include/cjong4/manager` と `src/manager` は、coreの判定・遷移を組み合わせて対局を進行します。

- 現在のフェーズとプレイヤーに対する合法アクションの収集
- `cj4_player_view` の生成
- プレイヤーデリゲートの呼び出し
- ロン、ポン、チーなど競合する応答の優先順位解決
- 選択結果に対応するcoreの状態遷移の実行

`cj4m_step()` は入力状態を直接変更せず、1回の選択または解決を進めた状態値を返します。

### player

`include/cjong4/player` と `src/player` は、マスク済みの `cj4_player_view`
だけを入力とするプレイヤー向けの `cj4p_*` 解析APIを提供します。

### 利用側

利用側は山を用意し、4人分の `cj4m_player_delegate` を提供して `cj4m_step()` を呼び出します。デリゲートには、マスク済みビューと合法アクションだけが渡されます。

UI表示、AI探索、ネットワーク同期、ログ保存は利用側の責務です。これらの副作用をライブラリ内部へ持ち込みません。

## 状態モデル

### 物理牌と `locations`

牌IDは0から135までの物理牌を表し、同じ牌種の4枚も別の牌として扱います。`cj4_mahjong.locations[tile_id]` は各物理牌について次の4バイトを保持します。

1. 局開始時の山位置
2. 捨牌情報
3. 手牌または面子の配置情報
4. 局全体の捨牌履歴情報

`cj4_location` は4個の `uint8_t` をこの順序で並べるため、ホストのエンディアンに依存しません。各バイトの未使用値は `CJ4_LOCATION_NONE`（`0xFF`）です。4バイトすべてが未使用値の場合、その物理牌の位置情報全体が不明であることを表します。

#### `wall`: 局開始時の山位置

| 値 | 意味 |
| --- | --- |
| `0`〜`135` | 局開始時に物理牌が置かれていた山位置 |
| `0xFF` | 山位置が不明 |

`wall` は牌をツモった後も変更しません。完全状態では全物理牌に一意な山位置を保持します。プレイヤービューでは、まだ公開できない牌の山位置を `0xFF` にマスクできます。山位置から物理牌を取得するときは `cj4_get_wall_tile()` が `locations` を走査します。

#### `discard`: 捨牌情報

ビット配置は `tppnnnnn` です。

| ビット | 記号 | 意味 |
| --- | --- | --- |
| 7 | `t` | `0`: 手出し、`1`: ツモ切り |
| 6〜5 | `pp` | 捨てたプレイヤー。`0`〜`3` |
| 4〜0 | `nnnnn` | そのプレイヤー内の捨牌番号。`0`〜`30` |

`nnnnn = 31` は `0xFF` との衝突を避けるため無効です。捨牌でない牌は `discard = 0xFF` とします。他家に鳴かれて面子へ移った後もこのバイトは保持するため、鳴かれた元捨牌のプレイヤー、順番、手出しかツモ切りかを復元できます。

読み取りには次のアクセサーを使用します。

- `cj4_location_is_discard()`
- `cj4_location_discard_player()`
- `cj4_location_discard_index()`
- `cj4_location_discard_is_tsumogiri()`

#### `placement`: 手牌・面子情報

未使用値は `0xFF` です。手牌と面子では異なる形式を使用します。

手牌のビット配置は `0pp00000` です。

| ビット | 記号 | 意味 |
| --- | --- | --- |
| 7 | `0` | 手牌であることを表す |
| 6〜5 | `pp` | 手牌の所有プレイヤー。`0`〜`3` |
| 4〜0 | `00000` | 常に0 |

手牌内の並び順とツモ牌の区別は `placement` に持ちません。ツモ牌は `cj4_mahjong.draw_tile` で識別します。

面子のビット配置は `1ppggttt` です。

| ビット | 記号 | 意味 |
| --- | --- | --- |
| 7 | `1` | 面子であることを表す |
| 6〜5 | `pp` | 面子の所有プレイヤー。`0`〜`3` |
| 4〜3 | `gg` | そのプレイヤー内の面子グループ番号。`0`〜`3` |
| 2〜0 | `ttt` | 面子種別 |

面子種別は次の値を使用します。

| `ttt` | 列挙値 | 意味 |
| --- | --- | --- |
| `000` | `CJ4_MELD_CHI` | チー |
| `001` | `CJ4_MELD_PON` | ポン |
| `010` | `CJ4_MELD_MINKAN` | 大明槓 |
| `011` | `CJ4_MELD_ANKAN` | 暗槓 |
| `100` | `CJ4_MELD_KAKAN` | 加槓 |
| `101`、`110` | 予約 | 現在は使用しない |
| `111` | `CJ4_MELD_INVALID` | 無効 |

同じ所有プレイヤーとグループ番号を持つ3枚または4枚を集めて1つの面子を復元します。他家から鳴いた牌は `discard` も保持しているため、面子内のどの物理牌が誰の捨牌だったかを識別できます。

読み取りには次のアクセサーを使用します。

- `cj4_location_is_hand()`
- `cj4_location_is_meld()`
- `cj4_location_placement_player()`
- `cj4_location_meld_group()`
- `cj4_location_meld_type()`

#### `discard_history`: 局全体の捨牌履歴

ビット配置は `rggggggg` です。

| ビット | 記号 | 意味 |
| --- | --- | --- |
| 7 | `r` | `1`: 立直宣言牌、`0`: 通常の捨牌 |
| 6〜0 | `ggggggg` | 局全体の捨牌順。`0`〜`85` |

捨てられていない牌は `discard_history = 0xFF` とします。鳴かれた後も履歴を保持するため、河から消えた牌を含めて局全体の捨牌順と立直宣言牌を復元できます。

読み取りには次のアクセサーを使用します。

- `cj4_location_is_discard_history()`
- `cj4_location_discard_history_index()`
- `cj4_location_discard_is_riichi()`

#### 代表的な組み合わせ

ここでは次の記号を使用します。

| 記号 | 意味 |
| --- | --- |
| `WW` | 有効な局開始時の山位置 |
| `DD` | 有効な捨牌情報 |
| `HP` | 有効な手牌の `placement` |
| `MP` | 有効な面子の `placement` |
| `HH` | 有効な捨牌履歴 |
| `FF` | `CJ4_LOCATION_NONE` |

以下の表は、ライブラリの正規の状態遷移で生成される有効な状態を対象とします。呼び出し側が公開構造体のフィールドを直接変更して作った不正な組み合わせは含みません。

##### 通常状態（`cj4_mahjong.locations`）

完全情報を持つ通常状態では、全物理牌の `wall` が有効です。成立し得る組み合わせは次のとおりです。

| 牌の状態 | `wall` | `discard` | `placement` | `discard_history` |
| --- | --- | --- | --- | --- |
| 山または王牌に残っている牌 | `WW` | `FF` | `FF` | `FF` |
| プレイヤーの手牌 | `WW` | `FF` | `HP` | `FF` |
| 河にある有効な捨牌 | `WW` | `DD` | `FF` | `HH` |
| 手牌から面子へ移した牌 | `WW` | `FF` | `MP` | `FF` |
| 他家の捨牌から面子へ移した牌 | `WW` | `DD` | `MP` | `HH` |

捨牌が鳴かれると、`placement` だけが面子情報へ変わり、`discard` と `discard_history` は残ります。したがって、通常状態に `WW DD MP HH` は存在しますが、捨牌情報だけを失った `WW FF MP HH` は存在しません。また、完全状態では `wall = FF` および4バイトすべてが `FF` の物理牌は存在しません。

##### プレイヤー状態（`cj4_player_view.locations`）

プレイヤー状態では、ビューの対象プレイヤーを「自分」、それ以外を「他家」とします。`cj4m_make_player_view()` は、牌そのものの公開情報を残しつつ、元の山位置を知ることができない場合は `wall` だけを `FF` にし、牌自体が非公開の場合は4バイトすべてを `FF` にします。

成立し得る組み合わせは次のとおりです。

| ビューから見た牌の状態 | `wall` | `discard` | `placement` | `discard_history` |
| --- | --- | --- | --- | --- |
| 非公開の山・王牌、または他家の手牌 | `FF` | `FF` | `FF` | `FF` |
| 公開済みのドラ表示牌 | `WW` | `FF` | `FF` | `FF` |
| 自分の手牌 | `WW` | `FF` | `HP` | `FF` |
| 自分が捨てた河の牌 | `WW` | `DD` | `FF` | `HH` |
| 他家がツモ切りした河の牌 | `WW` | `DD` | `FF` | `HH` |
| 他家が手出しした河の牌 | `FF` | `DD` | `FF` | `HH` |
| 自分の手牌から自分の面子へ移した牌 | `WW` | `FF` | `MP` | `FF` |
| 捨牌から自分の面子へ移した牌 | `WW` | `DD` | `MP` | `HH` |
| 他家の手牌から他家の面子へ移した牌 | `FF` | `FF` | `MP` | `FF` |
| 他家の面子にある、自分が捨てた牌またはツモ切りされた牌 | `WW` | `DD` | `MP` | `HH` |
| 他家の面子にある、自分以外の他家が手出しした牌 | `FF` | `DD` | `MP` | `HH` |

`wall` を公開する条件は、自分の手牌、自分の面子、自分が捨てた牌、ツモ切りされた牌、公開済みドラ表示牌のいずれかです。面子と捨牌は公開情報なので、元の山位置を隠す場合も `placement`、`discard`、`discard_history` は保持します。

同じバイト構成でも意味が異なる場合があります。たとえば `WW DD MP HH` は、自分の面子にある鳴き牌、自分が他家に鳴かせた牌、または他家がツモ切りして鳴かれた牌を表し得ます。所有者と元の捨牌者は `placement` と `discard` のプレイヤービットから区別します。

1牌の情報を値として取得するときは `cj4_location_get()` を使用します。無効な牌IDまたは `NULL` の配列を渡した場合は、4バイトすべてが `CJ4_LOCATION_NONE` の値を返します。

山、手牌、捨牌、面子の重複配列は正規状態に持ちません。必要な情報は `locations` を走査して復元します。ツモ牌、最新捨牌、山の進行位置など、処理上頻繁に参照する小さな値だけを `cj4_mahjong` に直接保持します。

この決定は[ADR 0001](adr/0001-use-locations-as-canonical-tile-state.md)に記録しています。

### パック済み進行情報

フェーズ、現在プレイヤー、立直、一発、振り聴、包、局結果などは、意味ごとに定義したマスクとシフトを使って小さな整数へ格納します。公開の読み取りアクセサーと内部の更新処理は同じ定数を参照し、ビット配置の不一致を防ぎます。

以下の図では左端をビット7、右端をビット0とします。プレイヤー別のビットは、最下位側からプレイヤー0、1、2、3の順です。

#### `progress`: フェーズと進行プレイヤー

ビット配置は `cfppssss` です。

| ビット | 記号 | 意味 | 読み取りアクセサー |
| --- | --- | --- | --- |
| 7 | `c` | 槍槓による和了を評価する状態 | `cj4_state_is_chankan()` |
| 6 | `f` | 鳴きで中断されていない局開始直後の一巡目 | `cj4_state_first_turn()` |
| 5〜4 | `pp` | 現在処理中のプレイヤー。`0`〜`3` | `cj4_state_current_player()` |
| 3〜0 | `ssss` | `cj4_phase` の値 | `cj4_state_phase()` |

`ssss` には `CJ4_PHASE_DRAW` から `CJ4_PHASE_GAME_END` までのフェーズを格納します。`f` は全員の最初の巡目が終わった場合、またはチー・ポン・槓で最初の一巡が中断された場合に0になります。

| `ssss` | 列挙値 | 意味 |
| --- | --- | --- |
| `0000` | `CJ4_PHASE_DRAW` | ツモ後のアクション選択 |
| `0001` | `CJ4_PHASE_KAKAN_RESOLVE` | 加槓に対する槍槓応答の解決 |
| `0010` | `CJ4_PHASE_ANKAN_RESOLVE` | 暗槓に対する国士無双の槍槓応答の解決 |
| `0011` | `CJ4_PHASE_AFTER_CALL` | チー・ポン成立後の打牌選択 |
| `0100` | `CJ4_PHASE_DISCARD` | 捨牌に対するロン・ポン・チー・大明槓応答の解決 |
| `0101` | `CJ4_PHASE_ROUND_END` | 局終了後、精算前 |
| `0110` | `CJ4_PHASE_SETTLE` | 精算済みで、次局または対局終了を決定する状態 |
| `0111` | `CJ4_PHASE_GAME_END` | 対局終了 |

#### `riichi_ippatsu`: 立直・一発

ビット配置は `iiiirrrr` です。

| ビット | 意味 | 読み取りアクセサー |
| --- | --- | --- |
| 7〜4 | プレイヤー3〜0の一発有効フラグ | `cj4_state_is_ippatsu(state, player)` |
| 3〜0 | プレイヤー3〜0の立直成立フラグ | `cj4_state_is_riichi(state, player)` |

たとえばビット0はプレイヤー0の立直、ビット4はプレイヤー0の一発を表します。

#### `furiten`: 一時振り聴・立直振り聴

ビット配置は `RRRRTTTT` です。

| ビット | 意味 | 読み取りアクセサー |
| --- | --- | --- |
| 7〜4 | プレイヤー3〜0の立直振り聴フラグ | `cj4_state_riichi_furiten(state, player)` |
| 3〜0 | プレイヤー3〜0の一時振り聴フラグ | `cj4_state_temporary_furiten(state, player)` |

捨牌による恒久的な振り聴は、各プレイヤーの捨牌履歴と現在の待ちから導出するため、このフィールドには保持しません。

#### `double_riichi_pending`: ダブル立直と立直成立待ち

ビット配置は `dpppDDDD` です。

| ビット | 記号 | 意味 | 読み取りアクセサー |
| --- | --- | --- | --- |
| 7 | `d` | 成立待ちの立直がダブル立直である | `cj4_state_pending_riichi_is_double()` |
| 6〜4 | `ppp` | 立直成立待ちのプレイヤー。`0`〜`3`、`7`は成立待ちなし | `cj4_state_has_pending_riichi()`、`cj4_state_pending_riichi_player()` |
| 3〜0 | `DDDD` | プレイヤー3〜0のダブル立直成立フラグ | `cj4_state_double_riichi(state, player)` |

立直宣言牌に対する応答がすべて解決するまで、立直棒の支払いと立直成立を保留するために `dppp` を使います。`ppp` の4〜6は予約値です。

#### `draw_turns`: プレイヤー別のツモ巡

各プレイヤーに2ビットを割り当てます。

| ビット | プレイヤー |
| --- | --- |
| 1〜0 | プレイヤー0 |
| 3〜2 | プレイヤー1 |
| 5〜4 | プレイヤー2 |
| 7〜6 | プレイヤー3 |

各2ビットの意味は次のとおりです。

| 値 | 意味 |
| --- | --- |
| `0` | まだ通常ツモを行っていない |
| `1` | 最初の通常ツモを行った |
| `2` | 2回目以降の通常ツモを行った |
| `3` | 予約値 |

読み取りには `cj4_state_draw_turn(state, player)` を使用します。九種九牌、ダブル立直、天和・地和など、最初の巡目に依存する判定で参照します。

#### `pao`: 責任払い

`pao` は2バイトで、各プレイヤーに4ビットを割り当てます。

| 配列とビット | 対象プレイヤー |
| --- | --- |
| `pao[0]` の3〜0 | プレイヤー0 |
| `pao[0]` の7〜4 | プレイヤー1 |
| `pao[1]` の3〜0 | プレイヤー2 |
| `pao[1]` の7〜4 | プレイヤー3 |

各4ビットの配置は `ttpp` です。

| ビット | 記号 | 意味 |
| --- | --- | --- |
| 3〜2 | `tt` | `cj4_pao_type` |
| 1〜0 | `pp` | 責任を負うプレイヤー。`0`〜`3` |

`tt` は `0`: 責任払いなし、`1`: 大三元、`2`: 大四喜、`3`: 四槓子です。責任払いなしの場合、`pp` は参照しません。読み取りには `cj4_state_pao_type()` と `cj4_state_pao_player()` を使用します。

#### `round_result`: 局の終了結果

ビット配置は `rraaattt` です。

| ビット | 記号 | 意味 | 読み取りアクセサー |
| --- | --- | --- | --- |
| 7〜6 | `rr` | 予約。現在は0 | なし |
| 5〜3 | `aaa` | `cj4_abortive_draw_reason` | `cj4_state_abortive_reason()` |
| 2〜0 | `ttt` | `cj4_round_end_type` | `cj4_state_round_end_type()` |

`ttt` は `0`: 未終了、`1`: ツモ、`2`: ロン、`3`: 荒牌流局、`4`: 途中流局です。`aaa` は `0`: 理由なし、`1`: 九種九牌、`2`: 四風連打、`3`: 四家立直、`4`: 四槓散了、`5`: 三家和です。

#### `winner_mask`: 和了者

| ビット | 意味 |
| --- | --- |
| 3〜0 | プレイヤー3〜0が和了者かを表すフラグ |
| 7〜4 | 予約。現在は0 |

ツモでは1ビット、複数ロンでは複数ビットを設定できます。`cj4_state_is_winner()` で個別に判定し、`cj4_state_winner_count()` で和了者数を取得します。和了牌の物理牌IDは `winning_tile` に保持します。

`progress` から `winning_tile` までのパック済み進行・局結果領域は合計10バイトです。ビット値を直接読み書きせず、公開の `cj4_state_*` 読み取りアクセサーと、内部専用の更新アクセサーを使用します。

### パックされていない状態フィールド

`cj4_mahjong` はパック済みフィールドのほかに、次の状態を直接保持します。

| フィールド | 意味 |
| --- | --- |
| `locations` | 136枚の物理牌の正規位置情報 |
| `scores` | プレイヤーごとの現在得点 |
| `round_wind` | 現在の場風 |
| `dealer` | 現在の親 |
| `honba` | 現在の本場数 |
| `riichi_sticks` | 供託されている立直棒の本数 |
| `winning_tile` | 和了牌の物理牌ID。和了でない場合は `CJ4_TILE_ID_INVALID` |
| `draw_tile` | 現在のツモ牌。ツモ牌がない場合は `CJ4_TILE_ID_INVALID` |
| `last_discard_tile` | 最新捨牌の物理牌ID。捨牌がない場合は `CJ4_TILE_ID_INVALID` |
| `pending_kakan_tile` | 槍槓判定中の加槓牌。該当しない場合は `CJ4_TILE_ID_INVALID` |
| `pending_ankan_tile` | 暗槓に対する国士無双の槍槓判定に使う代表牌 |
| `pending_ankan_tiles` | 暗槓成立時に面子へ移す4枚の物理牌ID |
| `wall_pos` | 次に通常ツモする山位置 |
| `dead_wall_draw_count` | 使用済み嶺上牌の枚数。`0`〜`4` |
| `dora_count` | 公開済みドラ表示牌数 |
| `pending_kan_dora_count` | 後めくりルールで公開待ちの槓ドラ表示牌数 |
| `discard_count` | 次の捨牌へ割り当てる局全体の捨牌履歴番号 |
| `next_round_wind` | 精算で決定した次局の場風 |
| `next_dealer` | 精算で決定した次局の親 |
| `settlement_should_end` | 精算結果により対局を終了する場合は1 |

`pending_kakan_tile`、`pending_ankan_tile`、`pending_ankan_tiles` は対応する槓の解決中に有効です。`pending_ankan_tile` は槍槓可否とプレイヤービューの生成、4枚の配列は暗槓成立時の状態更新に使います。槍槓によるロンが成立した場合は、和了結果の再構築に必要な対象牌を局終了状態まで保持します。槓の成立または局の処理が完了した後は無効牌IDに戻します。

### 値による状態遷移

公開状態遷移は、入力の `cj4_mahjong` を基に遷移後の値を生成します。グローバルな可変状態や隠れたキャッシュを使わないため、同じ状態と同じ引数からは同じ結果が得られます。

この決定は[ADR 0002](adr/0002-use-value-based-pure-state-transitions.md)に記録しています。

## 公開情報の分離

`cj4_mahjong` は山や他家の手牌を含む完全状態です。プレイヤーデリゲートへ完全状態を渡さず、`cj4m_make_player_view()` がプレイヤーごとの `cj4_player_view` を生成します。

ビューの `locations` では、自分の手牌と公開済み情報を残し、山や他家の手牌などを不明値でマスクします。ツモ牌や槍槓対象牌のようにフェーズ上必要な情報だけを専用フィールドで公開します。

この決定は[ADR 0003](adr/0003-provide-masked-player-views.md)に記録しています。

## 主要な処理フロー

局中の基本フローは次のとおりです。

```text
ツモ
→ ツモ和了・暗槓・加槓・立直・打牌の候補を収集
→ プレイヤーが1つ選択
→ 打牌を記録
→ ロン・ポン・チー・大明槓・パスの候補を各プレイヤーから収集
→ 優先順位を解決
→ 次のツモ、鳴き後の打牌、または局終了へ進む
→ 精算
→ 次局または対局終了へ進む
```

暗槓と加槓では、槍槓判定を行う解決フェーズを経てから槓を成立させます。槓ドラの公開時点はルール設定と槓種別に従い、公開待ちの件数を状態に保持します。

## 依存方向

依存方向は次の一方向を基本とします。

```text
利用側
  ↓
manager 公開API
  ↓
core 公開API
  ↓
core 内部実装
```

- coreはmanagerへ依存しません。
- managerはcoreの公開型と公開操作を組み合わせます。
- 公開ヘッダーは `include/cjong4` に置きます。
- 内部専用の生成・更新処理は `src` に置き、インストール対象にしません。
- テストは必要に応じて内部関数も検証しますが、そのために製品コードの公開範囲を広げません。

## 維持する不変条件

- 有効な牌IDは0から135で、同じ物理牌が同時に複数の現在位置を持たない
- 完全状態では各牌の元山位置が一意である
- 手牌、捨牌、面子、ドラ表示牌は `locations` から決定的に復元できる
- 面子の牌数、牌種、面子種別、所有者、グループ番号が整合する
- 状態のフェーズと、ツモ牌・最新捨牌・槓対象牌などの補助フィールドが整合する
- プレイヤービューに山と他家の手牌を公開しない
- coreの状態遷移はグローバルな可変状態や動的確保へ依存しない
- 同じ入力状態、ルール、アクションから同じ出力状態が得られる

## 変更時の指針

- 牌配置の新しい重複キャッシュを追加する前に、`locations` から導出できないか確認します。
- 公開状態遷移は値を返す形を維持します。
- 新しい公開情報は、完全状態とプレイヤービューの双方で可視性を検討します。
- 重要な設計上の選択や既存方針の変更は、実装と同時にADRへ記録します。
- テストは関心事ごとのファイルへ置き、共通の状態準備処理は `tests/test_support.*` を利用します。
